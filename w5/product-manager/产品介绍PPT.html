Solution

DataSpeak：一条安全的数据问答流水线

🗣️ 自然语言提问→ 🧠 LLM 生成 SQL
校验失败自动带反馈重试→ 🛡️ 安全校验
只读/封锁表列/危险函数→ 📦 只读执行
超时+行数上限→ ✅ 结果校验
置信度评分→ 📊 答案+SQL+追踪ID

对提问的人

30 秒自助拿数，附生成 SQL 与置信度 —— 每个数字可复核、可追溯（request_id 贯穿全链路日志）。

对管理员

封锁表/列清单化、只读事务、限流熔断、Prometheus 指标 —— 开放数据，风险可控。

Key Features

四个"说到做到"的核心能力

🗣️

自然语言查数

基于库 schema 生成 SQL，支持"仅出 SQL"模式供分析师二次加工。

🗄️

多库一体

一个入口查多个库，按请求精确路由，绝不串库；未指定且多库时明确提示。

🛡️

安全护栏

封锁表/封锁列/危险函数/只读事务四道闸，命中即拒绝并说明原因。

📈

生产可观测

请求量/延迟/拦截/Token 指标 + 限流排队 + 熔断自愈 + 退避重试。

以上能力均已实现并有 297 个自动化测试守护（w5 研发交付）。

Security by Default

护栏不是口号，是四道闸

闸门机制示例
① 语句白名单SQL 解析后仅放行 SELECT（写操作需显式开启，DDL 恒禁）DELETE FROM users → 拒绝
② 敏感对象封锁SECURITY_BLOCKED_TABLES / _COLUMNS（支持 table.column 精确封锁）SELECT password → 拒绝
③ 危险函数拦截pg_sleep / 文件读写 / dblink 等 19+ 函数黑名单SELECT pg_sleep(100) → 拒绝
④ 执行层兜底只读事务 + search_path 锁定 + 超时/行数上限 + 可选只读角色漏网之鱼也写不进库

拦截事件计入 pg_mcp_sql_rejected_total 指标 —— 谁在试探、试了什么，一目了然。

Trustworthy Answers

每个答案都自带"成分表"

SQL
生成语句全透明，口径可人工复核
0-100
置信度评分，<70 黄色警示并给出口径建议
request_id
追踪 ID 贯穿生成→校验→执行日志，审计零成本

设计哲学：不确定就明说—— 模糊口径的问题不会被包装成确定答案。

Architecture

引擎架构（pg-mcp）

MCP 客户端 / Web 前端→ Server（FastMCP）→ Orchestrator 编排器
追踪·限流·重试·指标
SQLGenerator（LLM） ⇄ SQLValidator（安全策略） → SQLExecutor ×N
每库一个 · 只读事务 → PostgreSQL ×N

弹性层

双层令牌限流（请求/LLM）、指数退避、熔断器 —— 坏天气降级不雪崩。

观测层

Prometheus 指标 + request_id 上下文贯穿 + JSON 日志脱敏。

配置层

多库 JSON 声明、安全策略、限流参数全部环境变量驱动。

# DataSpeak 产品需求文档（PRD）

> 产品岗交付 · ① 产品文档。产品载体：`w5/pg-mcp`（自然语言 → SQL 的 PostgreSQL MCP 服务）。
> 配套交付：② 交互原型 `prototype.html`；③ 产品介绍 PPT `产品介绍PPT.html`。

---

## 1. 问题与机会

**问题**：业务/运营/数据分析师每天大量重复"帮我查一下…"的需求。会 SQL 的人被查数请求淹没；
不会 SQL 的人提需求要排期、等半天，口径还经常对不上。

**机会**：LLM 已经能可靠地把结构化 schema + 自然语言翻译成 SQL。把"翻译 + 安全执行"做成
服务，让提问的人 30 秒内自己拿到答案，让会 SQL 的人回到真正复杂的工作上。

**一句话定位**：DataSpeak —— 让团队用自然语言安全地查询公司 PostgreSQL 数据库。

## 2. 目标用户与场景

| 用户 | 典型场景 | 核心诉求 |
|---|---|---|
| 业务/运营人员 | "上周注册但没下单的用户有多少？" | 快、不用求人、数字可信 |
| 数据分析师 | 高频取数需求分流；快速探索陌生库 | 生成的 SQL 可见可改、口径可追溯 |
| 平台/DBA 管理员 | 向业务开放数据但控风险 | 只读、敏感表封锁、限流、全程审计 |

## 3. 产品原则

1. **安全默认**：只读执行、敏感表/列封锁、危险函数拦截，默认全部开启且不可被提问绕过；
2. **答案可信**：每个答案附生成 SQL、置信度、request_id，可复核可追溯；
3. **容量自保**：限流 + 熔断 + 退避，坏天气下降级而不是雪崩；
4. **多库一体**：一套界面查多个库，库间口径隔离，绝不串库。

## 4. 功能需求

### P0（MVP，对应 pg-mcp 已实现能力）

| 编号 | 功能 | 描述 | 验收 |
|---|---|---|---|
| F-01 | 自然语言查数 | 输入问题 → 返回数据表 + 生成的 SQL | 平均 P50 ≤ 8s |
| F-02 | 仅生成 SQL 模式 | `return_type=sql`，只给 SQL 不执行 | 分析师可复制二次加工 |
| F-03 | 多库切换 | 界面选择目标库；未选且多库时提示选择 | 请求路由到所择库，绝不串库 |
| F-04 | 安全护栏 | 只读、封锁表/列、危险函数拦截；命中即拒绝并解释原因 | 拦截响应含具体违规对象 |
| F-05 | 结果可信标注 | 附置信度（0-100）与低置信度提醒 | <70 分黄色警示条 |
| F-06 | 全链路追踪 | 每次回答带 request_id，可检索全程日志 | 支持客服/审计按 ID 追查 |
| F-07 | 限流与排队 | 并发超限先排队，超时返回友好提示 | 超限请求得到明确文案而非报错堆栈 |

### P1（体验增强）

| 编号 | 功能 | 描述 |
|---|---|---|
| F-08 | 图表化结果 | 行列结果一键转柱状/折线图 |
| F-09 | 常用问题收藏 | 保存问题为"我的报表"，一键重跑 |
| F-10 | 结果解读 | LLM 用一句业务语言解释结果含义 |
| F-11 | EXPLAIN 诊断 | `allow_explain=true` 时展示查询计划，辅助性能分析 |

### 非功能需求

- **性能**：P50 ≤ 8s / P95 ≤ 20s（含 LLM）；单库并发 ≥ 10（`RESILIENCE_QUERY_RATE_LIMIT` 可配）；
- **安全**：数据库账号最小权限；应用层只读事务；敏感对象封锁；日志脱敏；
- **可观测**：Prometheus 指标（请求量/延迟/拦截/Token 消耗）、JSON 日志、request_id 贯穿；
- **可用性**：LLM 瞬态故障自动退避重试；持续故障熔断并快速返回。

## 5. 关键流程（MVP）

```
用户提问 → 选择目标库（单库自动选中）
        → LLM 依据该库 schema 生成 SQL（校验失败自动带反馈重试）
        → 安全校验：只读 / 封锁表列 / 危险函数 ── 命中 → 拒绝 + 原因说明
        → 只读事务执行（超时/行数上限保护）
        → LLM 结果校验给出置信度
        → 返回：数据表 + SQL + 置信度 + request_id
```

## 6. 成功指标

| 指标 | 目标 |
|---|---|
| 提问→拿答案的完成率 | ≥ 90% |
| 结果采纳率（置信度 ≥70 且用户未追问） | ≥ 80% |
| 数据团队被打断次数（查数类） | 下降 60% |
| 安全拦截准确率（拦截即违规） | 100%（宁拦勿漏） |

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| LLM 生成错误 SQL 误导决策 | 置信度标注 + SQL 全透明 + 口径问题走反馈闭环 |
| 敏感数据经提问外泄 | 封锁表/列 + 只读 + 日志脱敏三道闸 |
| LLM 成本失控 | Token 计量指标 + 限流 + 缓存高频问题（P1） |
| 多库口径混淆 | 库选择前置强提示，响应携带目标库名 |
